# 技術ノートの記録

引数: `$ARGUMENTS`

作業中に得た技術的な知見を `~/tech-notes` に記録する。メイン会話が内容と方針を決め、`model-routing:explorer` が既存ノートとの重複を調べ、`model-routing:coder` が執筆する。`model-routing` プラグインが入っていなければ、メイン会話が explorer / coder の作業も自分で行う。

## 0. 前提の確認

- `~/tech-notes` が無ければ、止めてユーザーに報告する
- `~/tech-notes/CLAUDE.md` を読む。ノートの書き方（frontmatter・見出し構成）、匿名化ルール、置き場所（`til/` かカテゴリか）、ファイル名の規則はすべてそこに従う。このスキルにはルールを書き写していないので、必ず読む

## 1. 残す内容を決める（メイン会話）

- 引数と直近の会話から、残す知見を選ぶ。業務ドメイン固有の話は残さず、一般化できる技術的な部分だけを取り出す
- 次を決める
  - タイトル案
  - 結論（1〜3 行）
  - 背景・再現条件
  - confidence（実際に試したか）
  - 確認したバージョン
  - 参考 URL
  - 検索用キーワード
- 知見が複数あれば、1 知見 1 ノートに分ける
- 話題がはっきりしないとき、匿名化の判断に迷う情報があるときだけユーザーに確認する。それ以外は確認せずに進める

## 2. 既存ノートの重複確認（`model-routing:explorer`）

キーワードを渡し、`~/tech-notes` 配下の `*.md`（`README.md`・`CLAUDE.md` を除く）を grep させる。次を返させる。

- 似た話題のノートのパスと frontmatter（title・tags）
- 既存のカテゴリフォルダの一覧
- 既存ノートで使われているタグの一覧

## 3. 書き方を決める（メイン会話）

- 同じ話題のノートがあれば、新規作成せず追記する
- 新規なら、置き場所・slug・タグを決める（既存タグを優先する）

## 4. 執筆（`model-routing:coder`）

- 渡すもの: 対象パス（新規か追記か）、1 で決めた内容、タグ、今日の日付
- coder にも `~/tech-notes/CLAUDE.md` を読ませ、書き方と匿名化ルールに従わせる
- 業務リポジトリのコードやログはそのまま貼らせず、最小限の再現コードに書き起こさせる
- カテゴリを新しく作った場合は、`README.md` の目次も更新させる
- 追記の場合は、`updated` を今日の日付にさせる

## 5. 確認（メイン会話）

- `git -C ~/tech-notes diff` と新規ファイルを読み、`CLAUDE.md` の匿名化ルールに照らして漏れがないか確認する。漏れがあれば直させる
- 作った・追記したファイルのパスと要約をユーザーに報告する

## 6. commit

- commit / push はユーザーが明示したときだけ行う。commit の name / email は `~/tech-notes` のローカル設定を使い、上書きしない
- pre-commit フック（gitleaks と禁止語チェック）で止まったら、指摘された箇所を一般化して直し、再度 commit する。`--no-verify` でフックを飛ばさない
